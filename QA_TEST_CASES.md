# Studio QA test cases — execution contract

Qwen: read-only project and Edit-mode DataModel. Use Roblox Studio MCP for Play start/stop, input, runtime inspection, Output and screenshots. Never create/edit/delete files or Edit-mode objects, commit, switch branch, publish or patch code. If MCP cannot inject a control or inspect a field, mark BLOCKED with precise tool limitation, **not PASS**. Use an owner-supplied synced build; capture build tag, commit, Studio version, OS/device, Play mode and time. Do not claim a test ran from a written plan. Observe server state via read-only runtime explorer/logs where available; if not, record the verification gap.

Each case: record steps and actual measurements/visuals, screenshot names or links, Output errors, observed PASS/FAIL/BLOCKED. Thresholds are acceptance behavior; tuning numbers in design are provisional. Reset between cases where specified; do not edit game data. A case fails when observed behavior contradicts expected; do not invent a bug.

## Report format (write report outside source tree; submit to owner/Arena)

`Build/branch/commit; Studio/OS/device; case ID; result PASS|FAIL|BLOCKED; exact Play steps; expected; actual with values; screenshot/video paths; Output errors/warnings; runtime state observed; confidence/inspection limits; smallest actionable reproduction; relevant regressions to rerun.` Qwen reports what it observed only. Arena triages FAIL and implements smallest fix, runs tests/build, commits/pushes with authorization, then Qwen reruns failed and related regression cases. Owner accepts after all required PASS.
